# Дополнительные спецификации проекта «LeafLog»

Настоящий документ определяет нефункциональные требования, ограничения, свойства качества обслуживания и архитектурные атрибуты веб-приложения «LeafLog», дополняющие функциональные требования SRS.

## 1. Надежность (Reliability)
* Система должна обеспечивать регулярное ежедневное резервное копирование базы данных PostgreSQL не реже 1 раза в сутки.
* При сбое отправки email-уведомления задача должна сохраняться в системе, а ошибка отправки — логироваться в системном журнале.
* При временной недоступности внешнего API справочника система обязана автоматически переключаться на использование локального кэша (`Species`) без потери работоспособности.

## 2. Безопасность и защита данных (Security)
* Все передаваемые данные между клиентом и сервером должны шифроваться с использованием протокола HTTPS (`REQ-SEC-001`).
* Пароли пользователей должны храниться в базе данных исключительно в виде криптографических хэшей с использованием алгоритма BCrypt (`REQ-SEC-002`).
* Доступ к личным данным растений, задачам и записям дневника должен иметь только их прямой владелец (строгая изоляция данных пользователей через `REQ-SEC-003`).
* Доступ к административной панели управления справочником должен быть строго ограничен ролью администратора (`REQ-SEC-004`, статус функции — *Deferred*).

## 3. Производительность (Performance)
* Время загрузки главной страницы приложения со списком растений не должно превышать 3 секунд при наличии в коллекции 100 растений (`REQ-PERF-001`).
* Время отклика сервера при выполнении типовых CRUD-операций не должно превышать 500 мс (`REQ-PERF-002`)[cite: 12].
* Бэкенд-архитектура должна стабильно выдерживать не менее 100 одновременных активных пользователей без деградации производительности (`REQ-PERF-003`).

## 4. Доступность и развертывание (Availability & Deployment)
* Общая доступность веб-приложения должна составлять не менее 99% в месяц (`REQ-AVAIL-001`).
* Плановые технические работы и обслуживание должны проводиться исключительно в ночное время (с 02:00 до 05:00) (`REQ-AVAIL-002`).
* Приложение спроектировано по монолитной архитектуре: бэкенд (Java Spring Boot + Thymeleaf) и база данных (PostgreSQL) развертываются совместно на едином виртуальном сервере (VPS) (`REQ-DIST-001`).

## 5. Ограничения проектирования и стандарты (Constraints)
* Программный стек жестко зафиксирован: Java 21, Spring Boot 3, Thymeleaf, PostgreSQL и система сборки Maven (`REQ-COMP-001`, `REQ-INST-001`, `REQ-BUILD-001`).
* Интерфейс приложения должен корректно адаптироваться и отображаться на экранах любых устройств с разрешением от 360px до 1920px (`REQ-INT-005`).
* Проект должен полностью соответствовать нормам законодательства Республики Беларусь о защите персональных данных (`REQ-COMP-002`).
