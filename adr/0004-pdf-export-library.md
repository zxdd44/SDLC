# Выбор библиотеки для экспорта дневника в PDF

## Контекст и постановка задачи
В ходе второго раунда переговоров Заказчик запросил экспорт дневника растения в PDF (`REQ-FUNC-013`). Нужна библиотека, которая формирует PDF с русским текстом и фотографиями и быстро внедряется.

## Драйверы решения
* Скорость разработки (необходимость уложиться в жёсткий дедлайн MVP).
* Открытая лицензия.
* Поддержка кириллицы и вставки изображений.

## Рассмотренные варианты
* **Вариант 1:** OpenPDF
* **Вариант 2:** Apache PDFBox
* **Вариант 3:** iText 7

## Итог решения
Выбран вариант **«OpenPDF»**, так как у неё открытая лицензия и простой API для абзацев и изображений, что укладывается в 3 дня разработки.

### Последствия
* **Хорошо**, потому что документ собирается из текста и фото несколькими вызовами.
* **Плохо**, потому что для кириллицы нужно встроить шрифт в приложение.

### Подтверждение
Автотест: PDF с русским текстом и фото формируется и открывается без ошибок.

## Плюсы и минусы вариантов

### OpenPDF
* Хорошо, потому что открытая лицензия и простой API.
* Плохо, потому что возможностей меньше, чем у iText 7.

### Apache PDFBox
* Хорошо, потому что лицензия Apache 2.0.
* Плохо, потому что низкоуровневый API, раскладку нужно считать вручную.

### iText 7
* Хорошо, потому что богатые возможности.
* Плохо, потому что лицензия AGPL (иначе коммерческая) накладывает обязательства.

## Дополнительная информация

* Связанные элементы SDD: `005-interface`.
