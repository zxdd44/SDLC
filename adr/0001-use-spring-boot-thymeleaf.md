# Выбор Java Spring Boot и Thymeleaf для приложения

## Контекст и постановка задачи
Для проекта «LeafLog» нужно создать безопасное веб-приложение с авторизацией, базой данных и серверным рендерингом страниц. SRS фиксирует Java 21 и Thymeleaf (`REQ-INT-009`).

## Драйверы решения
* Безопасность (хэширование паролей, защита от CSRF, изоляция данных пользователей, `REQ-SEC-002`, `REQ-SEC-003`).
* Скорость разработки (команда Senior + Junior, жёсткий срок).
* Единый деплой на один сервер (`REQ-DIST-001`).

## Рассмотренные варианты
* Java + Spring Boot + Thymeleaf
* Java + Spring Boot + React (SPA)
* Python + Django

## Итог решения
Выбран вариант **«Java + Spring Boot + Thymeleaf»**, так как он закрывает требования безопасности встроенными средствами и даёт один артефакт для развёртывания.

### Последствия
* **Хорошо**, потому что Spring Security и Spring Data JPA покрывают безопасность и работу с БД, а приложение собирается в один JAR.
* **Плохо**, потому что интерфейс менее интерактивен, чем SPA: страницы перезагружаются.

### Подтверждение
Проверка через код-ревью и автотесты безопасности (пользователь не имеет доступа к чужим растениям).

## Плюсы и минусы вариантов

### Java + Spring Boot + Thymeleaf
* Хорошо, потому что простая архитектура и готовые модули безопасности.
* Плохо, потому что меньше интерактивности на клиенте.

### Java + Spring Boot + React (SPA)
* Хорошо, потому что богатый интерфейс.
* Плохо, потому что две кодовые базы и отдельное REST API, что дольше в разработке.

### Python + Django
* Хорошо, потому что быстрая разработка.
* Плохо, потому что противоречит заданному SRS стеку.

## Дополнительная информация
* Связанные требования SRS: `REQ-INT-009`, `REQ-SEC-002`, `REQ-SEC-003`.
* Связанные элементы SDD: `002-composition`, `003-structure`.

* **Статическая структура (диаграмма классов, `uml/class.png`):**
  * **Классы и атрибуты.** Класс изображается прямоугольником из трёх секций: имя, атрибуты (`-name : String`), операции (`+addCareTask(task : CareTask) : void`). Видимость: `-` приватная, `+` публичная, `#` защищённая, `~` пакетная. Конструкторы помечены `«create»`.
  * **Обобщение (наследование).** Сплошная линия с полым треугольником. Все сущности (`User`, `Plant`, `Species`, `CareTask`, `DiaryEntry`, `Photo`, `ReminderLog`) наследуют абстрактный `BaseEntity` с общим идентификатором `id`, чтобы не дублировать его в каждом классе. Репозитории `PlantRepository`, `CareTaskRepository`, `ReminderLogRepository` расширяют интерфейс `JpaRepository`.
  * **Реализация интерфейса.** Пунктирная линия с полым треугольником: `OpenPdfGenerator` реализует `PdfGenerator`. Контроллер зависит от интерфейса, а не от конкретной библиотеки.
  * **Композиция.** Сплошная линия с закрашенным ромбом у «целого»: `User` → `Plant`, `Plant` → `CareTask`, `Plant` → `DiaryEntry`, `DiaryEntry` → `Photo`, `CareTask` → `ReminderLog`. Часть не существует без целого и удаляется вместе с ним (каскадное удаление).
  * **Агрегация.** Полый ромбик: `Plant` ссылается на `Species`. Вид растения является общим справочным объектом, и удаление растения его не удаляет.
  * **Ассоциация.** Сплошная стрелка: `ThymeleafController` → `PlantService`, `CareService`; сервисы → репозитории. Кратности (`1`, `0..*`) показывают, сколько объектов участвует в связи, а стрелка указывает направление навигации.
  * **Зависимость.** Пунктирная стрелка со стереотипом: `«use»` (класс использует другой), `«create»` (`PlantService` создаёт `PlantData`).
  * **Принципы добавления операций.** Каждая операция добавлена по потребности слоя: `PlantRepository.findByIdAndUserId` обеспечивает изоляцию данных (`REQ-SEC-003`), `CareTask.markDone` и `isOverdue` реализуют жизненный цикл задачи (`006-state-dynamics`), `ReminderScheduler.sendDailyReminders` запускает ежесуточную рассылку.
